> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 스펙 §7의 나머지 Provider 15개(winget, scoop, choco, apt, dnf, pacman, nvm-windows, fnm, volta, pyenv, rustup, sdkman, pnpm, pipx, cargo)를 추가해 세 OS의 개발 환경을 모두 스캔한다.

**Architecture:** 계획 1의 `Provider` trait과 `FakeEnv` fixture 테스트 패턴을 그대로 따른다. 내보내기는 계획 2가 `ItemDetails`로 이미 처리하므로 Provider는 스캔만 구현한다. winget·sdkman에 필요한 임시 파일과 심볼릭 링크 읽기를 위해 `Env`에 메서드 3개를 추가한다.

**Tech Stack:** Rust, `repot-core`

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` (§7)

**선행 계획:** 계획 1(`2026-11-02-01-core-scan.md`), 계획 2(`2026-11-02-02-export.md`)

## Global Constraints

- 계획 1·2의 Global Constraints를 따른다(특히 "출력 해석 실패 → Provider 전체 실패", "최상위 패키지만").
- fixture는 실제 도구 출력을 녹화한 것이 가장 좋다. 해당 OS가 없으면 이 계획에 적힌 형식대로 손으로 만들고, 계획 5의 CI 실제 스캔 테스트로 검증한다.
- 로케일에 따라 바뀌는 사람용 출력(예: `pacman -Qi`의 필드 이름)은 파싱하지 않는다. 사용자 지정 출력 형식이나 로컬 데이터 파일을 쓴다.
- Item id 형식: `<provider>:<이름>` 또는 계획 1처럼 `<provider>:<종류>:<이름>`. 각 Task에 명시한 형식을 따른다.
- 패키지 매니저 Provider의 `detect`는 OS도 확인한다(예: winget은 Windows에서만). 다른 OS에 같은 이름의 명령이 있어도 잘못 잡지 않기 위해서다.
- 알려진 한계(스펙 §15에 추가): winget은 `winget` 소스 패키지만(msstore 제외), volta는 런타임만(volta로 설치한 전역 패키지 제외), rustup은 툴체인만(component·target 제외), scoop은 기본 bucket 이외의 사용자 지정 bucket URL을 보존하지 않는다.

## Review Focus

1. **winget export가 0이 아닌 종료 코드를 내면서도 파일을 쓴 경우**: 일부 패키지가 소스에 없으면 winget은 경고와 함께 실패 코드를 내지만 파일은 정상이다. 파일이 해석되면 성공으로 봐야 한다. → Task 2 `nonzero_exit_with_valid_file`
2. **choco의 `.install` 의존성 패키지**: `git`과 `git.install`이 둘 다 보이면 `git`만 남아야 한다. → Task 4 `drops_dependency_packages`
3. **apt 설치 초기 목록이 없는 기기**: `/var/log/installer/initial-status.gz`가 없으면 거르지 않고 그대로 보여줘야 하며 실패하면 안 된다. → Task 5 `no_initial_status_is_not_an_error`
4. **rustup의 새·옛 출력 형식**: `(default)`와 `(active, default)` 둘 다 기본 툴체인으로 인식해야 한다. → Task 10 `parses_old_and_new_default_markers`
5. **pnpm 전역 패키지가 없는 경우**: `pnpm ls -g --json`이 `[]`나 dependencies 없는 객체를 내도 실패하지 않고 0개여야 한다. → Task 12 `empty_global_list`

### Task 4: choco

**Files:** Create `crates/core/src/providers/choco.rs`, Test `tests/choco_test.rs`

**Interfaces:** `pub struct Choco;` (`id() == "choco"`, `Category::PackageManager`)

동작:
- `detect`: Windows이고 `which("choco")`
- `choco list --limit-output` → `id|version` 줄. `chocolatey` 자체는 제외.
- 각 패키지의 nuspec: `<root>/lib/<id>/<id>.nuspec`(root는 `ChocolateyInstall` 환경 변수, 없으면 `C:/ProgramData/chocolatey`). 정규식으로 `<summary>…</summary>`, `<description>…</description>`, `<dependency id="…"`를 뽑는다(XML 파서 없이). 설명은 summary, 없으면 description의 첫 줄. `&amp;`, `&lt;`, `&gt;`, `&quot;`, `&apos;`만 디코딩. nuspec을 못 읽으면 설명 없음·의존성 없음으로 처리.
- **다른 설치 패키지의 의존성으로 등장하는 id(대소문자 무시)는 제외한다.** (스펙 §7)

- [ ] **Step 1: 실패하는 테스트 작성**

```rust
fn nuspec(summary: &str, deps: &[&str]) -> String {
    let d: String = deps.iter().map(|id| format!(r#"<dependency id="{id}" version="1.0" />"#)).collect();
    format!(r#"<?xml version="1.0"?><package><metadata><summary>{summary}</summary><dependencies>{d}</dependencies></metadata></package>"#)
}

#[test]
fn drops_dependency_packages() {   // Review Focus 2
    let lib = "C:/ProgramData/chocolatey/lib";
    let env = FakeEnv::new(Os::Windows, "C:/Users/t")
        .with_command("choco", &["list", "--limit-output"],
            "chocolatey|2.3.0\ngit|2.47.0\ngit.install|2.47.0\n7zip|24.8.0\n7zip.install|24.8.0\n")
        .with_file(format!("{lib}/git/git.nuspec"), &nuspec("Git (Install)", &["git.install"]))
        .with_file(format!("{lib}/git.install/git.install.nuspec"), &nuspec("Git (Install)", &[]))
        .with_file(format!("{lib}/7zip/7zip.nuspec"), &nuspec("7-Zip &amp; tools", &["7zip.install"]))
        .with_file(format!("{lib}/7zip.install/7zip.install.nuspec"), &nuspec("7-Zip", &[]));
    let items = Choco.scan(&env).unwrap();
    assert_eq!(items.iter().map(|i| i.id.as_str()).collect::<Vec<_>>(), vec!["choco:git", "choco:7zip"]);
    assert_eq!(items[1].description.as_deref(), Some("7-Zip & tools"));
    assert_eq!(items[0].version.as_deref(), Some("2.47.0"));
}
```

### Task 5: apt

**Files:** Create `crates/core/src/providers/apt.rs`, Test `tests/apt_test.rs`

**Interfaces:** `pub struct Apt;` (`id() == "apt"`, `Category::PackageManager`)

동작:
- `detect`: Linux이고 `which("apt-mark")`
- `apt-mark showmanual` → 이름 목록. `name:arch` 형태면 그대로 이름으로 쓰되, 조회 키는 `:` 앞부분.
- `dpkg-query -W -f=${Package}\t${Version}\t${binary:Summary}\n` → 이름별 버전·요약. (`-f=` 뒤 문자열은 한 인자로 전달, `\t`와 `\n`은 dpkg가 해석하는 문자 그대로)
- 초기 설치 목록 거르기: `/var/log/installer/initial-status.gz`가 있으면 `gzip -dc <그 경로>`의 `Package: <name>` 줄을 모아 제외한다. 파일이 없거나 `gzip`이 실패하면 거르지 않는다(오류 아님). (스펙 §7)
- id `apt:<name>`, `Package { Apt, Package }`, `SameOs`, 이름순.

- [ ] **Step 1: 실패하는 테스트 작성**

```rust
const DPKG_ARGS: &[&str] = &["-W", "-f=${Package}\\t${Version}\\t${binary:Summary}\\n"];

fn env(with_initial: bool) -> FakeEnv {
    let mut e = FakeEnv::new(Os::Linux(LinuxFamily::Debian), "/home/t")
        .with_command("apt-mark", &["showmanual"], "curl\nripgrep\nbase-files\n")
        .with_command("dpkg-query", DPKG_ARGS,
            "curl\t8.5.0\tcommand line tool for transferring data with URL syntax\nripgrep\t14.1.0\tRecursively searches directories for a regex pattern\nbase-files\t13\tDebian base system miscellaneous files\n");
    if with_initial {
        e = e.with_file("/var/log/installer/initial-status.gz", "<gz>")
            .with_command("gzip", &["-dc", "/var/log/installer/initial-status.gz"], "Package: base-files\nStatus: install ok installed\n\nPackage: curl\n");
    }
    e
}

#[test]
fn filters_initial_packages() {
    let ids: Vec<_> = Apt.scan(&env(true)).unwrap().into_iter().map(|i| i.id).collect();
    assert_eq!(ids, vec!["apt:ripgrep"]);
}

#[test]
fn no_initial_status_is_not_an_error() {   // Review Focus 3
    let items = Apt.scan(&env(false)).unwrap();
    assert_eq!(items.iter().map(|i| i.id.as_str()).collect::<Vec<_>>(), vec!["apt:base-files", "apt:curl", "apt:ripgrep"]);
    assert_eq!(items[1].description.as_deref(), Some("command line tool for transferring data with URL syntax"));
}
```

> `DPKG_ARGS`의 `\\t`·`\\n`은 Rust 문자열에서 백슬래시 두 글자다. 구현도 같은 인자를 넘긴다.
