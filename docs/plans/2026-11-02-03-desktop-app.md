# Repot 계획 3: 데스크톱 앱 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tauri 2 + React로 시작 → 스캔 진행 → 검토 → 내보내기 → 완료 화면을 만들어, macOS에서 GUI로 스캔부터 내보내기까지 끝낼 수 있게 한다.

**Architecture:** `apps/desktop/src-tauri`(Rust, `repot-desktop`)는 `repot-core`를 호출하는 얇은 명령 층이고, 스캔 결과와 환경은 앱 상태(`AppState`)에 메모리로만 보관한다. `apps/desktop/src`(React + TypeScript + Vite)는 `useReducer` 하나로 화면 상태를 관리하고, 선택·필터 같은 로직은 `logic.ts`의 순수 함수로 분리해 Vitest로 테스트한다. 목적지 OS별 사용 가능 판정은 Rust가 계산해 넘겨준다(TS로 중복 구현하지 않음).

**Tech Stack:** Tauri 2, tauri-plugin-dialog 2, tauri-plugin-opener 2, React, TypeScript, Vite, Vitest, pnpm

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` (§4, §5, §11)

**선행 계획:** 계획 1(`2026-11-02-01-core-scan.md`), 계획 2(`2026-11-02-02-export.md`)

## Global Constraints

- 계획 1·2의 Global Constraints를 따른다.
- 프론트엔드에는 shell 권한을 주지 않는다. capability는 `core:default`, `dialog:allow-open`만. 폴더 열기는 Rust 명령이 마지막 내보내기 경로만 연다. (스펙 §5)
- 스캔 결과는 디스크에 저장하지 않는다. (스펙 §5)
- 패키지 이름: npm `@repot/desktop`(private), Rust `repot-desktop`. 앱 identifier `io.github.junjuny0227.repot`, productName `Repot`, 버전 `0.1.0`.
- 의존성 버전은 설치 시점의 최신 안정 버전(Tauri는 2.x)을 쓰고 lockfile(`pnpm-lock.yaml`, `Cargo.lock`)을 커밋한다. UI 라이브러리(컴포넌트 킷, 상태 관리 라이브러리)는 쓰지 않는다.
- **UI 문구는 모두 `src/strings.ts` 한 파일에 모은다.** MVP는 영어로 작성하고, 한국어 등 다른 언어는 이 파일만 바꾸면 되게 한다. 컴포넌트에 문구를 직접 쓰지 않는다.
- 스펙 §5와의 차이: 명령 4개에 `availability_for`(목적지 OS 변경 시 판정)와 `open_export_folder`를 더해 6개다.
- 기본 체크 상태: 목적지 OS에서 사용 가능한 항목 전부. 목적지 OS를 바꿔 사용할 수 없게 된 항목은 체크 해제. (스펙 §11)

## Review Focus

1. **스캔 중 목적지 OS 변경**: 스캔이 끝나기 전에 사용자가 화면을 떠날 수 없어야 하고, 스캔이 끝나면 그때의 목적지 OS로 판정해야 한다. → Task 4 `scan_finished_uses_current_target`
2. **비밀정보 원문 허용을 켠 뒤 항목 체크 해제**: 체크를 해제한 항목의 원문 허용 줄이 `Selection`에 남으면 안 된다. → Task 4 `selection_drops_reveals_of_unchecked_items`
3. **선택한 항목이 0개**: 내보내기 버튼이 비활성화되어야 한다. → Task 4 `can_export_requires_selection`
4. **Rust와 TypeScript의 JSON 모양 불일치**: 실제 Rust 직렬화 결과(fixture)로 TS 로직을 돌려 어긋나면 테스트가 실패해야 한다. → Task 3 fixture 생성, Task 4 전체 테스트가 fixture를 사용
5. **내보내기 실패(쓰기 권한 없는 폴더 선택)**: 앱이 멈추지 않고 오류 문구를 보여준 뒤 다시 시도할 수 있어야 한다. → Task 4 `export_error_keeps_export_screen`
