# Repot 계획 12: Repot 파일과 이 기기 비교

**Goal:** 새 기기에서 옛 기기의 `repot.json`을 연 뒤 "이 기기와 비교"를 누르면, 이 기기를 스캔해 각 항목을 "이미 있음 / 내용 다름 / 없음"으로 나눠 보여준다. 처음 선택은 "없음"과 "내용 다름"만 켜서, 빠진 것만 골라 내보내게 한다.

**Architecture:** `repot-core`에 `compare` 모듈을 더한다. 판정은 항목을 목적지 설치 단계(`Step`)로 바꾼 뒤, 이 기기 스캔 결과를 같은 방식으로 바꾼 단계와 맞춰 본다. 복원 스크립트가 "이미 있으면 건너뜀"으로 확인하는 대상과 같은 것을 비교하므로, 화면의 "이미 있음"과 스크립트의 "건너뜀"이 같은 뜻이 된다. 설정 파일은 목적지 경로가 같으면 내용을 비교한다. 데스크톱 세션은 열린 파일 옆에 이 기기 스캔 결과를 하나 더 들고, 판정은 목적지가 바뀔 때마다 다시 계산한다.

**Tech Stack:** Rust, React, TypeScript, Vitest

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` §2·4·5·11·13·15·16

## Global Constraints

- **새 의존성 없음.** `Cargo.lock`, `pnpm-lock.yaml`, Tauri capability는 바뀌지 않는다.
- **기기를 바꾸지 않는다.** 비교는 기존 스캔(읽기)과 같은 Provider를 그대로 쓴다. 설정 파일 내용 비교도 `Env::read_file`로 읽기만 한다.
- **비교 결과는 내보내기를 바꾸지 않는다.** 판정은 처음 선택과 표시에만 쓴다. 사용자는 "이미 있음" 항목도 다시 켤 수 있고, 내보낸 스크립트는 지금처럼 실행할 때 다시 확인한다.
- **판정은 목적지가 이 기기 OS일 때만 한다.** 다른 OS를 목적지로 고르면 비교 표시를 지운다(그 기기를 스캔한 게 아니므로).
- **core는 문장을 만들지 않는다.** 판정은 enum이고, 문구는 네 로캘(en·ko·ja·zh-Hans)에 둔다.
- **비밀정보:** 설정 파일 내용 비교는 양쪽 모두 같은 방식으로 가린 뒤 비교한다. 화면에 내용 차이(diff)는 보여주지 않는다.
- AGENTS.md는 하위 작업자가 고치지 않는다.

## 결정과 이유

**왜 설치 단계로 비교하는가.** 항목 id(`brew:formula:ripgrep`)는 OS마다 달라서, Mac 파일과 Windows 기기를 id로 맞출 수 없다. 반면 "목적지에서 실행할 단계"는 대응표를 거친 뒤의 이름(`winget BurntSushi.ripgrep.MSVC`)이라 이 기기 스캔 결과와 같은 말로 비교된다. 단계 변환은 내보내기가 이미 쓰는 `steps_for_target`을 그대로 쓰므로, 비교와 내보내기의 이름이 어긋날 수 없다.

**같은 단계의 기준.**

| 단계 | 같다고 보는 조건 |
|---|---|
| 패키지 설치 | 매니저·종류가 같고 이름이 대소문자 무시로 같다. Scoop은 bucket을 떼고 앱 이름만 비교한다(스캔 결과에 bucket이 없음). |
| 탭/버킷 추가 | 매니저와 이름(대소문자 무시) |
| 런타임 | 도구(목적지 대응 도구)·런타임·버전이 모두 같다. 기본 버전 여부는 보지 않는다. |
| 전역 패키지 | 매니저와 이름 |
| 에디터 확장 | 에디터와 확장 ID(대소문자 무시) |
| 셸 플러그인 | 설치 위치(`TargetPath`) |
| 설정 파일 | 설치 위치가 같으면 "있음". 그다음 내용 비교: 파일 쪽 내용을 목적지 형태로 준비한 것과 이 기기 파일을 같은 방식으로 가린 것이 같으면 "이미 있음", 다르면 "내용 다름" |

- 대응된 패키지의 Scoop bucket 추가 단계는 판정에서 뺀다. 항목의 본 단계(앱 설치)만 본다.
- 다른 매니저로 설치된 경우(파일은 winget인데 이 기기에는 Scoop으로 있음)는 "없음"이다. 내보낼 스크립트가 쓰는 매니저 기준이기 때문이다. §15에 적는다.
- 런타임은 다른 버전만 있으면 "없음"이다. 스크립트가 그 버전을 설치하기 때문이다.

**왜 이 기기 스캔을 따로 들고 있는가.** 열린 파일 세션의 항목은 파일에서 온 것이고, 비교에는 이 기기 항목이 따로 필요하다. 세션에 `machine: Option<ScanResult>`를 더하면 "어느 파일을 어느 기기와 비교했나"가 한곳에 묶인다. 새 파일을 열거나 새로 스캔하면 지운다.

**처음 선택.** 비교가 끝나면 "사용 가능하고 이미 있음이 아닌 항목"만 켠다. "내용 다름"은 켠다. 사용자가 고른 내용을 새 기기로 덮어쓰려는 경우가 많고, 스크립트는 덮어쓰기 전에 백업한다.

## 모델 변경 (core)

```rust
// crates/core/src/compare.rs
pub enum Presence { Present, Differs, Missing }
pub fn compare(
    items: &[Item], source: Os, target: Target, configs: &(impl ConfigSource + ?Sized),
    machine: &[Item], machine_os: Os, machine_configs: &(impl ConfigSource + ?Sized),
) -> HashMap<String, Presence>;   // 목적지에서 사용할 수 없는 항목은 빠진다
```

## Tauri 명령 변경

| 명령 | 변경 |
|---|---|
| `scan_machine` (새로 추가) | 이 기기를 스캔해(진행 상황은 기존 `scan://progress`) 현재 세션의 `machine`에 넣는다. 세션 항목은 바꾸지 않는다. 세션이 없으면 오류. |
| `presence_for` (새로 추가) | 목적지 `Target`을 받아 `compare` 결과를 돌려준다. 목적지 OS가 이 기기 OS와 다르거나 `machine`이 없으면 빈 맵. |
| `scan`, `open_snapshot` | 세션을 바꾸면서 `machine`을 지운다. |

## UI 변경

- 검토 화면(열린 파일일 때만): 사이드바 아래 출처 표시 밑에 "이 기기와 비교" 버튼. 누르면 목적지를 이 기기 OS로 바꾸고 스캔 진행 화면을 보여준 뒤 검토 화면으로 돌아온다.
- 목록: 항목마다 "이미 있음"(회색), "내용 다름"(주황) 표시를 붙인다. "없음"은 표시하지 않는다(기본 상태). 필터에 "이 기기에 없는 것만"을 더한다.
- 사이드바 출처 표시에 "이미 있음 n개, 내용 다름 m개" 요약을 더한다.
- 목적지를 다른 OS로 바꾸면 비교 표시와 요약이 사라지고, 다시 이 기기 OS로 돌아오면 다시 계산한다(재스캔 없이).
- 상세 패널: 판정과 그 이유(예: "winget BurntSushi.ripgrep.MSVC가 이미 설치되어 있습니다", "같은 위치에 내용이 다른 파일이 있습니다. 내보내면 백업한 뒤 덮어씁니다").

## Review Focus

1. 비교가 `steps_for_target`/`steps_for`를 재사용하고, 이름 변환을 따로 구현하지 않았는가.
2. 같은 OS(Mac→Mac)와 다른 OS(Mac 파일→Windows 기기, winget·Scoop)에서 판정 표 테스트가 있는가. Scoop bucket, 대소문자, 런타임 버전 차이, 다른 매니저 설치를 포함하는가.
3. 설정 파일 내용 비교가 양쪽 모두 가린 뒤 이뤄지고, 비밀 값이 판정 외 어디에도 나가지 않는가.
4. 목적지 OS가 이 기기와 다르면 판정이 비고, 새 파일 열기·새 스캔에서 `machine`이 지워지는가.
5. 처음 선택이 "없음·내용 다름"만이고, 사용자가 "이미 있음"을 다시 켤 수 있는가.
6. 네 로캘에 새 키가 모두 있는가.
