# Repot 계획 6: 제품 사이트 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 다른 인디 Mac 앱처럼 한 페이지짜리 정적 제품 사이트를 만들어 `https://junjuny0227.github.io/Repot/`에 올린다. 방문자의 OS에 맞는 설치 파일을 바로 받고, 앱이 하는 일과 하지 않는 일, 서명되지 않은 베타를 여는 방법을 한 화면에서 읽을 수 있게 한다.

**Architecture:** 같은 저장소의 `apps/site`(npm `@repot/site`, private)에 Vite + React + TypeScript 정적 앱을 둔다. 색과 글꼴 토큰은 `apps/desktop/src/styles/tokens.css`를 사이트 CSS에서 `@import`해 앱과 같은 macOS 팔레트를 그대로 쓰고, 웹 페이지에 맞는 글자 크기와 여백만 사이트 쪽 토큰으로 더한다. 다운로드 링크는 빌드할 때 `apps/desktop/src-tauri/tauri.conf.json`의 `version`으로 만든다(런타임 GitHub API 호출 없음). OS 판별과 링크 생성은 `src/downloads.ts`의 순수 함수로 두고 Vitest로 테스트한다. `main` push 때 `.github/workflows/pages.yml`이 빌드해 GitHub Pages에 배포한다.

**Tech Stack:** React, TypeScript, Vite, Vitest, pnpm, GitHub Actions(`actions/configure-pages`, `actions/upload-pages-artifact`, `actions/deploy-pages`)

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` (§3 핵심 원칙, §7 Provider 목록, §14 배포)

**선행 계획:** 계획 5(`2026-11-02-05-ci-release.md`). v0.1.0 사전 릴리스가 공개되어 있어야 다운로드 링크가 살아 있다.

## Global Constraints

- 계획 3·5의 Global Constraints를 따른다.
- **새 의존성 없음.** `apps/site/package.json`에는 `apps/desktop`이 이미 쓰는 패키지만 둔다: `react`, `react-dom`, `vite`, `@vitejs/plugin-react`, `typescript`, `vitest`, `@types/react`, `@types/react-dom`. 라우터, CSS 프레임워크, 아이콘 패키지, 분석 스크립트, 웹 폰트를 쓰지 않는다. 이미지 최적화도 패키지가 아니라 로컬 도구(`sips`, `cwebp`)로 한 번 하고 결과 파일을 커밋한다.
- 패키지 이름 `@repot/site`, Vite `base: "/Repot/"`. 사이트 문구는 영어이고 `src/content.ts` 한 파일에 모은다. 사실은 `README.md`와 스펙에 있는 것만 쓴다(기능을 지어내지 않는다).
- **사이트도 네트워크를 쓰지 않는다.** 런타임에 GitHub API, CDN, 외부 폰트·이미지를 부르지 않는다. 바깥으로 나가는 것은 사용자가 누르는 링크(GitHub, Releases 자산)뿐이다.
- `apps/desktop`은 고치지 않는다. 사이트가 데스크톱 파일 세 개(`tokens.css`, `tauri.conf.json`, `app-icon-macos.svg`)를 읽기만 하고, 데스크톱 빌드는 사이트를 모른다.
- 다운로드 URL 형식: `https://github.com/junjuny0227/Repot/releases/download/v<version>/<asset>`. 자산 파일 이름 틀은 `src/assets.json` 한 곳에 둔다(사이트와 Pages 워크플로가 같이 읽는다).
- macOS 네이티브 느낌(System Settings·Finder): 시스템 글꼴, 앱 토큰의 색, 그룹 상자, 시스템 강조색 버튼. 라이트·다크는 `prefers-color-scheme`, 움직임은 `prefers-reduced-motion`, 반투명은 `prefers-reduced-transparency`를 따른다. 시맨틱 HTML(`header`/`main`/`section`/`footer`, 제목 계층), 키보드 포커스 표시, 이미지 대체 텍스트.
- Pages 워크플로의 액션은 Node 24 런타임 메이저로 고정한다: `actions/configure-pages@v6`, `actions/upload-pages-artifact@v5`, `actions/deploy-pages@v5`. 나머지는 `ci.yml`과 같은 버전(`checkout@v6`, `pnpm/action-setup@v6`, `setup-node@v6`, Node 22).
- 원격 push, PR, 저장소 설정 변경(Pages 활성화)은 **실행 전에 사용자에게 확인을 받는다.**

## 결정과 이유

### 토큰 공유: 데스크톱 `tokens.css`를 사이트에서 `@import`

| 방법 | 장점 | 단점 |
|---|---|---|
| 복사 | 의존 없음 | 앱 색을 바꾸면 사이트가 조용히 어긋난다 |
| 공유 패키지(`packages/tokens`) | 깔끔한 방향 | 데스크톱 import 경로를 바꿔야 해서 데스크톱 빌드가 바뀐다 |
| **사이트가 데스크톱 파일을 `@import`** | 원본 하나, 데스크톱은 그대로 | 사이트가 데스크톱 파일 경로를 안다 |

세 번째를 고른다. 의존 방향이 사이트 → 데스크톱 한쪽뿐이라 데스크톱 빌드는 영향을 받지 않는다. 데스크톱 쪽 이름 변경으로 사이트가 깨지는 위험은 `tokens.test.ts`가 막는다(사이트 CSS의 모든 `var(--x)`가 두 토큰 파일 중 하나에 정의돼 있는지 확인). 앱 전용 값(`--titlebar-inset`, `data-platform`)은 사이트가 쓰지 않으므로 무해하다. 13px 본문 같은 앱 글자 크기는 웹 페이지에 작아서, 사이트는 `--site-*` 글자·여백 토큰을 따로 정의한다. 카테고리 아이콘(System Settings식 색 사각형)은 데스크톱 `icons.tsx`의 glyph 몇 개를 복사한다. 데스크톱 컴포넌트를 import하면 데스크톱 타입과 클래스 이름까지 따라오기 때문이다.

### 다운로드 링크: 빌드 시점 버전 상수

- `releases/latest`는 사전 릴리스만 있을 때 404다. 그래서 `tauri.conf.json`의 `version`을 `src/downloads.ts`에서 JSON import로 읽어 태그 `v<version>`의 자산 URL을 직접 만든다. 버전의 원본은 계획 5의 `check-version`이 이미 맞추는 그 값 하나다.
- 런타임 API 호출을 하지 않는다. 정적 사이트로 남고, 비인증 API의 시간당 60회 제한에도 걸리지 않는다.
- **버전을 올린 커밋이 릴리스 공개보다 먼저 `main`에 들어가면** 사이트 링크가 아직 없는 태그를 가리킨다. Pages 워크플로는 배포 전에 `gh release view v<version>`으로 그 릴리스가 공개(초안 아님)되어 있고 `assets.json`의 파일이 모두 붙어 있는지 확인하고, 아니면 실패해 이전 배포를 그대로 둔다. 릴리스를 공개하면 `release: published` 트리거로 다시 배포된다.
- 정식 릴리스(사전 릴리스 아님)가 생긴 뒤에는 고정 버전 URL을 그대로 써도 되고, 원하면 `https://github.com/junjuny0227/Repot/releases/latest/download/<asset>`로 바꿀 수 있다. 다만 자산 이름에 버전이 들어 있어서(`Repot_0.1.0_…`) `latest/download`도 결국 버전을 알아야 한다. 따라서 지금 방식을 유지하고, "Other downloads"의 Releases 목록 링크만 `releases/latest`로 바꾼다.

### OS 판별

- `navigator.userAgentData.platform`이 있으면(Chromium) 그것을, 없으면 `navigator.userAgent`를 본다. iPhone·iPad·Android는 데스크톱 앱 대상이 아니므로 `unknown`. iPadOS Safari는 `Macintosh`를 보내므로 `maxTouchPoints > 1`이면 `unknown`.
- macOS는 칩을 확실히 알 수 없다. Apple silicon 버튼을 기본으로 하고 Intel 버튼을 나란히 둔다. Chromium의 `getHighEntropyValues(["architecture"])`가 `x86`이면 Intel을 기본으로 바꾼다. 구분법 안내(Apple menu › About This Mac의 Chip/Processor)를 함께 보여준다.
- Windows는 `-setup.exe`, Linux는 `.AppImage`가 기본이다. 나머지 파일(`.msi`, `.deb`, `.rpm`)은 설치 섹션의 OS별 목록에 있다. `unknown`이면 기본 버튼이 설치 섹션으로 이동한다.

### 배포

- `.github/workflows/pages.yml`: `main` push(사이트에 영향을 주는 경로만), `release: published`, `workflow_dispatch`. 잡 `build`(검사·빌드·artifact 업로드)와 `deploy`(`environment: github-pages`). 권한은 `contents: read`, `pages: write`, `id-token: write`.
- GitHub Pages는 저장소 설정에서 **Source: GitHub Actions**로 한 번 켜야 한다(현재 꺼져 있음: `gh api repos/junjuny0227/Repot/pages` → 404). `GITHUB_TOKEN`으로는 켤 수 없어서 `configure-pages`의 `enablement`는 쓰지 않는다. 사용자 확인 후 Settings › Pages에서 켜거나 `gh api -X POST repos/junjuny0227/Repot/pages -f build_type=workflow`.

## Review Focus

1. **사이트 링크가 아직 공개되지 않은 릴리스를 가리킴**: 버전만 올라가고 릴리스가 초안이면 배포하지 말아야 한다. → Task 6 "Check the published release" 단계
2. **자산 이름 틀이 실제 릴리스와 다름**: `tauri-action`이 만드는 이름(`Repot_0.1.0_aarch64.dmg`, `Repot-0.1.0-1.x86_64.rpm` 등)과 하나라도 다르면 404 버튼이 생긴다. → Task 3 `asset URLs match the v0.1.0 release files`, Task 6 자산 검사
3. **iPad·Android를 데스크톱으로 오인**: iPadOS Safari의 `Macintosh`, Android의 `Linux`에 속아 설치 파일을 권하면 안 된다. → Task 3 `iPad and Android are not desktop platforms`
4. **데스크톱 토큰 이름 변경으로 사이트 색이 사라짐**: 정의되지 않은 `var(--x)`는 오류 없이 빈 값이 된다. → Task 1 `tokens.test.ts`
5. **base 경로 누락**: `base: "/Repot/"`가 없으면 Pages에서 CSS·이미지가 404다. → Task 7 빌드 결과의 `/Repot/assets/` 확인과 `vite preview` 확인
6. **서명 안 된 베타를 숨김**: 다운로드 버튼 바로 옆에 unsigned beta임을 쓰고, 첫 실행 방법은 README와 같은 내용이어야 한다. → Task 4 설치 섹션
