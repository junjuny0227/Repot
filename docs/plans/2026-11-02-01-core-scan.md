# Repot 계획 1: Core 기반과 스캔 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tauri와 무관한 `repot-core` 라이브러리에 도메인 모델, 환경 추상화, 병렬 스캔, 비밀정보 감지, 목적지 OS 판정, 그리고 카테고리별 대표 Provider 6개(brew, nvm, npm, vscode, git, shell)를 구현하고, 실제 기기를 스캔해 JSON으로 출력하는 예제를 만든다.

**Architecture:** Cargo workspace의 `crates/core` 하나. 모든 외부 접근(명령 실행, 파일 읽기)은 `Env` trait을 거치며, 테스트는 `FakeEnv`에 fixture를 넣어 실행한다. `scan()`은 Provider마다 스레드를 띄우고 하나의 마감 시각으로 타임아웃을 건다.

**Tech Stack:** Rust (edition 2024, stable), serde, serde_json, thiserror, regex, wait-timeout, tempfile(dev)

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md`

## Global Constraints

- 패키지 이름 `repot-core`, 라이브러리 이름 `repot_core`, 경로 `crates/core`. Rust edition 2024, `rust-toolchain.toml`은 `channel = "stable"`, `components = ["clippy", "rustfmt"]`.
- `repot-core`는 Tauri에 의존하지 않는다. (스펙 §5)
- core 어디에서도 네트워크 통신을 하지 않는다. (스펙 §3.4)
- 의존성은 `serde`(derive), `serde_json`, `thiserror`, `regex`, `wait-timeout`만. dev 의존성은 `tempfile`만. 그 밖의 crate가 필요하면 계획을 먼저 고친다.
- Provider 타임아웃 30초, 명령 타임아웃 30초. (스펙 §7)
- 직접 설치한 최상위 패키지만 항목으로 만든다. (스펙 §7)
- 출력 해석이 하나라도 실패하면 그 Provider 전체가 실패다. 일부만 해석한 항목을 돌려주지 않는다. (스펙 §12)
- 비밀정보 마스킹 문자열은 정확히 `<REDACTED>`이고, 값 부분만 바꾼다. (스펙 §8)
- 공개 모델 타입(`Item`부터 `ProviderReport`, `ProviderStatus`까지)은 모두 `Serialize`, `Deserialize`, `Debug`, `Clone`, `PartialEq`를 derive하고 `#[serde(rename_all = "camelCase")]`를 붙인다. 필드가 있는 variant를 가진 enum에는 `rename_all_fields = "camelCase"`도 붙인다(예: `otherProvider`). (계획 3에서 프론트엔드로 그대로 넘긴다.)
- core는 사람이 읽는 문장을 만들지 않는다. Finding과 판정 이유는 구조화된 데이터로 돌려주고, UI가 문장으로 바꾼다. 예외는 `catalog`의 내장 설명뿐이며 영어 한 문장으로 쓴다. (UI 언어는 계획 3에서 정한다.)
- 스펙 §6과의 차이: `ItemKind`는 `ItemDetails` variant로 대체한다. `Portability::Mapped`는 판정에 필요해서 `Mapped(RuntimeTool)`로 도구를 담는다. 내보내기는 Provider의 `export` 메서드 대신 `ItemDetails`를 해석하는 중앙 모듈(계획 2)이 맡는다. 그래서 `ItemDetails`에는 복원에 필요한 정보가 모두 들어 있어야 한다.

## Review Focus

1. **CRLF 줄바꿈 설정 파일**: Windows에서 만든 `.gitconfig`에 비밀정보가 있으면 줄 번호가 맞아야 하고, 마스킹 후에도 `\r\n`이 유지되어야 한다. → Task 3 `mask_preserves_crlf`

**감지 규칙** (스펙 §8):


| 규칙        | 패턴                                                                                                                                                                       | `name` |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------ |
| AWS       | `AKIA[0-9A-Z]{16}`                                                                                                                                                       | None   |
| GitHub    | `gh[pousr]_[A-Za-z0-9]{36,}`, `github_pat_[A-Za-z0-9_]{22,}`                                                                                                             | None   |
| Anthropic | `sk-ant-[A-Za-z0-9_-]{20,}`                                                                                                                                              | None   |
| OpenAI    | `sk-[A-Za-z0-9_-]{20,}`                                                                                                                                                  | None   |
| Slack     | `xox[abpr]-[A-Za-z0-9-]{10,}`                                                                                                                                            | None   |
| Google    | `AIza[0-9A-Za-z_-]{35}`                                                                                                                                                  | None   |
| URL 자격 증명 | `[a-zA-Z][a-zA-Z0-9+.-]*://([^/\s:@]+(:[^/\s@]+)?)@` → userinfo 부분                                                                                                       | None   |
| 개인 키      | `-----BEGIN [A-Z ]*PRIVATE KEY-----`부터 `-----END … PRIVATE KEY-----`까지 각 줄 전체                                                                                            | None   |
| 이름 기반     | `export NAME=값`, `NAME = 값`, `$env:NAME = 값`, fish `set [-옵션…] NAME 값` 중 이름(대소문자 무시)에 `TOKEN`, `SECRET`, `PASSWORD`, `PASSWD`, `API_KEY`, `ACCESS_KEY`, `PRIVATE_KEY` 포함 | 변수 이름  |


- 이름 기반 값: 감싼 따옴표(`"`, `'`)는 범위에서 뺀다. 따옴표를 벗긴 값이 비었거나 `$`로 시작하면 감지하지 않는다.
- **한 줄에서 범위가 겹치는 감지는 하나의 `SecretMatch`로 합친다.** 합쳐진 결과의 `name`은 구성 요소 중 이름이 있는 것을 쓴다.

pub trait Provider: Send + Sync {

pub enum ProviderError {
    #[error("`{command}` exited with code {code:?}")]
    CommandFailed { command: String, code: Option<i32>, stderr: String },
    #[error("could not parse output of `{command}`: {message}")]
    Parse { command: String, message: String },
    #[error("environment error: {0}")]

}

pub struct ScanResult { pub items: Vec<Item>, pub providers: Vec<ProviderReport> }
pub struct ProviderReport { pub id: String, pub category: Category, pub status: ProviderStatus }
pub enum ProviderStatus { Running, Ok { count: usize }, NotDetected, Failed { message: String, detail: String }, TimedOut }

pub fn scan(
    env: Arc<dyn Env>,
    providers: Vec<Arc<dyn Provider>>,

    on_progress: &(dyn Fn(&ProviderReport) + Sync),
) -> ScanResult;
