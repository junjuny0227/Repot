# Repot 계획 15: 명령줄 도구 `repot`

**Goal:** 앱 없이 터미널에서 스캔, `repot.json` 비교, 내보내기를 한다. 서버·원격 기기·자동화처럼 창을 띄울 수 없는 곳에서도 같은 복원 스크립트와 `repot.json`을 만든다.

**Architecture:** 새 crate `crates/cli`(패키지 `repot-cli`, 실행 파일 `repot`)가 `repot-core`를 그대로 부른다. 데스크톱 `commands.rs`에 있던 세션 로직(스캔 결과나 열린 파일, 설정 내용을 어디서 읽는지, 미리보기)과 처음 선택 규칙을 core의 `session` 모듈로 옮겨 앱과 CLI가 같은 코드를 쓴다. CLI는 그 위의 얇은 층으로, 인자 해석과 출력 문장만 맡는다.

**Tech Stack:** Rust(`clap` 추가), GitHub Actions

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` §2·4·5·13·14·16

## Global Constraints

- **새 의존성 하나:** `clap = { version = "4", features = ["derive"] }`(CLI crate에만). 테스트용 의존성은 더하지 않는다. CLI 테스트는 `FakeEnv`로 실행 함수를 직접 부르고, 실행 파일 테스트는 `env!("CARGO_BIN_EXE_repot")`과 `std::process::Command`로 한다.
- **앱과 같은 원칙:** CLI는 기기를 바꾸지 않는다. 스캔은 읽기만 하고, 쓰기는 `--out` 폴더의 내보내기 폴더 하나뿐이다. 복원 스크립트를 실행하지 않는다. 네트워크를 쓰지 않으며 자체 업데이트도 하지 않는다.
- **판정은 core 하나:** 사용 가능 여부, 비교, 처음 선택은 core 함수만 쓴다. CLI에 같은 규칙을 다시 쓰지 않는다.
- core는 계속 문장을 만들지 않는다. CLI 문장은 `crates/cli`에 영어로 둔다.
- AGENTS.md는 하위 작업자가 고치지 않는다.

## 결정과 이유

**명령.**

```
repot scan [--json]
repot compare <repot.json> [--json]
repot export [<repot.json>] [--to <os>] [--packages <manager>] [--format script|manifest]
             [--only-missing] [--include <id>]... [--exclude <id>]... [--out <dir>] [--dry-run]
```

- `scan`: 이 기기를 스캔해 분류별로 항목을 보여준다. 진행 상황은 stderr에 Provider별로 한 줄씩 쓴다.
- `compare`: 파일의 각 항목을 이 기기와 비교해 Already here / Different here / Missing으로 나눈다. 목적지는 이 기기 OS다(앱과 같은 조건).
- `export`: 파일을 주면 그 파일을, 안 주면 이 기기를 스캔한 결과를 내보낸다. 목적지 기본값은 이 기기 OS와 그 OS의 기본 매니저다. `--to`는 `macos`, `windows`, `linux-debian`, `linux-fedora`, `linux-arch`, `linux-other`. `--out` 기본값은 현재 폴더이고, 앱과 같은 이름의 새 폴더를 만든다. `--dry-run`은 만들 파일 목록과 경고만 보여주고 쓰지 않는다.

**처음 선택은 앱과 같다.** 목적지에서 쓸 수 있는 항목은 모두 선택, 파일의 `notExported` 항목은 선택하지 않음(계획 13), `--only-missing`이면 비교해서 Missing만 선택(계획 12, 목적지가 이 기기 OS가 아니면 오류). 그다음 `--include`/`--exclude`로 항목 id를 더하거나 뺀다. 이 규칙은 core `session::default_selection`으로 옮기고 Rust 테스트로 고정한다. 데스크톱 화면은 사용자가 체크를 바로 바꾸므로 TypeScript 쪽 같은 규칙(`logic.ts`)은 남기되, 같은 경우를 양쪽 테스트에 둔다.

**비밀정보는 항상 가린다.** 앱의 "원본으로 내보내기"는 줄을 보고 고르는 화면 결정이라 CLI에는 두지 않는다. 가린 줄이 있으면 개수와 항목을 stderr에 알린다.

**빠진 항목을 알린다.** 앱은 목적지에서 쓸 수 없는 항목을 회색으로 보여주지만 CLI에는 화면이 없으므로, 처음 선택에서 빠진 항목을 이유와 함께 stderr(`note: left out <name>: <reason>`)와 `--json`의 `leftOut`에 남긴다. 사용법 전체는 `crates/cli/README.md`와 번역본(`README.{ko,ja,zh-Hans}.md`)에 두고, README 4개와 사이트가 각자 같은 언어의 안내를 링크한다. 명령·옵션·출력 예시는 번역하지 않는다. `crates/cli/tests/guide_test.rs`가 clap의 명령·옵션·값이 네 안내 모두에 있는지, 번역본의 코드 블록과 절 구조가 영어판과 같은지 검사한다.

**출력.** 사람이 읽는 문장은 영어 한 가지다(도구 이름처럼 터미널에서 흔한 관례). 기계용은 `--json`으로 앱과 같은 serde 모양(`ScanResult`, `Presence` 맵, `ExportBundle`의 파일 목록과 경고)을 낸다. `--json` 모양은 0.x 동안 바뀔 수 있다고 README에 적는다. 오래 남는 형식은 `repot.json`뿐이다.

**종료 코드.** 0 성공(경고는 stderr), 1 실행 오류(파일 열기 실패, 잘못된 목적지 조합, 쓰기 실패), 2 사용법 오류(clap 기본). 확인 질문은 하지 않는다.

**배포.** 릴리스 워크플로에 CLI 빌드 작업을 더해 `repot-cli-<버전>-<target>.tar.gz`(macOS arm64·x64, Linux x64)와 `.zip`(Windows x64)을 같은 릴리스에 올린다. 서명은 없다(앱과 같다). Rust가 있는 사용자는 `cargo install --git https://github.com/junjuny0227/Repot repot-cli`로도 설치한다. 압축 파일을 손으로 PATH에 넣는 설치는 번거롭고 macOS에서는 브라우저로 받으면 quarantine에 막히므로, 자체 Homebrew tap(`junjuny0227/homebrew-tap`, `brew install junjuny0227/tap/repot`)과 Scoop bucket(`junjuny0227/scoop-bucket`)을 둔다. 자체 tap·bucket은 심사가 없다. 릴리스 워크플로가 공개 뒤 formula와 manifest의 버전·sha256을 고쳐 push하며, 그 저장소들에만 쓸 수 있는 fine-grained 토큰을 저장소 시크릿(`TAP_TOKEN`)으로 쓴다. 토큰은 사용자가 만들어 넣는다. homebrew-core·공식 Scoop bucket은 심사와 인지도 기준이 있어 지금은 하지 않는다. crates.io 게시는 core까지 함께 공개 API로 굳어지므로 뒤로 미룬다. 버전은 워크스페이스와 같고 `scripts/check-version.mjs`가 `crates/cli/Cargo.toml`도 확인한다.

## core 변경

```rust
// crates/core/src/session.rs
pub enum Configs { Live, Snapshot(Arc<Snapshot>) }
pub struct Session { pub source: Os, pub scan: ScanResult, pub configs: Configs, pub machine: Option<ScanResult>, pub not_exported: BTreeSet<String> }
impl Session {
    pub fn from_scan(source: Os, scan: ScanResult) -> Self;
    pub fn open(env: &dyn Env, path: &Path) -> Result<(Self, OpenedInfo), OpenError>; // 크기 검사 포함
    pub fn availability(&self, target: Target) -> HashMap<String, Availability>;
    pub fn presence(&self, env: &dyn Env, this_os: Os, target: Target) -> HashMap<String, Presence>;
    pub fn preview(&self, env: &dyn Env, selection: &Selection, target: Target, format: Format, meta: ExportMeta) -> ExportBundle;
}
pub fn default_selection(items: &[Item], avail: &HashMap<String, Availability>, not_exported: &BTreeSet<String>, presence: Option<&HashMap<String, Presence>>) -> Vec<String>;
```

데스크톱 `commands.rs`는 이 함수들을 부르는 얇은 층이 되고, 명령 이름·입출력은 바뀌지 않는다.

## Review Focus

1. 세션 이동 뒤 데스크톱 동작이 같은가(기존 Rust·Vitest 통과, 명령 모양 불변).
2. `default_selection`이 앱의 세 규칙(사용 가능, notExported 제외, 비교 후 Missing만)과 같은가.
3. CLI가 쓰는 곳이 `--out` 안의 새 폴더뿐이고, `--dry-run`은 아무것도 쓰지 않는가.
4. 잘못된 조합(`--packages`가 목적지와 맞지 않음, 다른 OS로 `--only-missing`, 없는 `--include` id)이 1로 끝나고 이유를 말하는가.
5. 릴리스 자산 이름과 개수, 초안 검사 스크립트에 CLI 파일이 들어갔는가.
6. tap·bucket 갱신이 공개된 릴리스에서만 돌고, 토큰이 그 저장소들에만 쓰기 권한을 갖는가.
