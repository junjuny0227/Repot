# Repot 계획 2: 내보내기 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 스캔한 항목과 사용자 선택을 받아 목적지 OS에 맞는 통합 스크립트(`restore.sh`/`restore.ps1`) 또는 네이티브 매니페스트 묶음을 만들고, 원자적으로 폴더에 쓴다.

**Architecture:** `ItemDetails` → 추상 단계 `Step` → (스크립트 렌더러 | 매니페스트 렌더러) → `ExportBundle`(메모리 속 파일 목록) → `write_export`(임시 폴더에 쓰고 이름 변경). 미리보기는 `ExportBundle`을 그대로 보여주고, 저장은 같은 번들을 디스크에 쓴다. 설정 파일은 내보낼 때 다시 읽어 마스킹과 OS 간 변환을 적용한다.

**Tech Stack:** Rust, `repot-core`(계획 1), 스냅샷 테스트용 `insta`(dev)

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` (§8, §9, §10)

**선행 계획:** `docs/plans/2026-11-02-01-core-scan.md`

## Global Constraints

- 계획 1의 Global Constraints를 모두 따른다. dev 의존성에 `insta`를 추가한다.
- 내보내기 폴더 이름은 `repot-export-<YYYY-MM-DD>`, 이미 있으면 `-2`, `-3`… (스펙 §10)
- 패키지 이름·버전·확장 ID·URL은 `^[A-Za-z0-9@._+/:-]+$`에 맞아야 한다. 맞지 않으면 그 항목은 내보내지 않고 경고한다. (스펙 §10)
- 설정 파일 내용은 스크립트 안에 넣지 않고 `files/` 아래에만 둔다. (스펙 §10)
- `restore.sh`는 bash 3.2, `restore.ps1`은 PowerShell 5.1에서 동작해야 한다. (스펙 §10)
- bash 스크립트는 `set -u`를 쓰지 않고 배열도 쓰지 않는다(bash 3.2에서 빈 배열 확장이 `set -u`와 충돌). 결과 목록은 줄바꿈으로 이어 붙인 문자열 변수에 쌓는다.
- 스크립트의 셸 값은 모두 작은따옴표로 감싼다. bash는 `'` → `'\''`, PowerShell은 `'` → `''`.
- 스크립트는 패키지 매니저·버전 관리자·oh-my-zsh를 설치하지 않는다. 없으면 안내 URL을 출력하고 그 단계들을 "건너뜀"으로 기록한다. (스펙 §10)
- 스크립트 종료 코드: 실패한 단계가 하나라도 있으면 1, 아니면 0. 계획 5의 스모크 테스트가 의존한다.
- 설정 파일 백업 이름은 `<대상 파일>.repot-backup-<YYYYMMDDHHMMSS>`. 대상 파일 내용이 이미 같으면 복사하지 않고 "건너뜀". (스펙 §10)
- 런타임은 정확한 버전, 전역 패키지·확장은 버전 없이(최신) 설치한다. (스펙 §10)
- 생성 파일(스크립트 출력 문구, README)의 문구는 영어다. UI 언어 결정(계획 3)과 별개로, 오픈소스 배포물이라 영어로 통일한다.
- `build_export`는 실패하지 않는다. 항목 단위 문제는 모두 `ExportWarning`으로 돌려준다. 디스크 쓰기 오류만 `write_export`의 `ExportError`다.

## Review Focus

1. **같은 대상 경로를 가진 항목 두 개**: Windows의 PowerShell 7 profile과 Windows PowerShell 5.1 profile은 둘 다 `TargetPath::PowerShellProfile`이다. 둘 다 체크되면 하나만 내보내고 경고해야 한다. → Task 7 `duplicate_target_keeps_first`
2. **스캔 이후 바뀐 설정 파일**: 내보낼 때 파일이 지워졌거나 권한이 바뀌었으면 앱이 실패하지 말고 그 항목만 경고해야 한다. → Task 7 `read_failure_becomes_warning`
3. **스크립트를 두 번 실행**: 두 번째 실행에서 백업 파일이 또 생기면 안 된다. → Task 4 `copy_step_backs_up_once`
4. **경로에 작은따옴표가 든 설정 파일**: `it's.json` 같은 이름이 스크립트를 깨뜨리면 안 된다. → Task 2 `quotes_single_quote`, Task 4 `bash_syntax_is_valid`
5. **쓰기 도중 실패**: 반쯤 만들어진 폴더가 남으면 안 된다. → Task 8 `failed_write_leaves_nothing`

### Task 3: 설정 파일 준비 (마스킹, OS 간 변환)

**Files:**

- Test: `crates/core/tests/export_payload_test.rs`

**Interfaces:**
- Consumes: 계획 1의 `secrets::{detect, mask}`, `providers::git::os_specific_lines`; Task 2의 `payload_path`, `os_label`
- Produces:

```rust
pub struct MaskedLine { pub file: String, pub line: u32, pub name: Option<String> }   // file: files/ 기준 경로
pub enum ExportNote {
    CommentedOsLine { file: String, line: u32, key: String },
    KeybindingsMayDiffer { file: String },
}
pub struct PreparedFile { pub path: String, pub contents: String, pub masked: Vec<MaskedLine>, pub notes: Vec<ExportNote> }

/// item은 ItemDetails::ConfigFile이어야 한다.
pub fn prepare_config(item: &Item, content: &str, reveal: &[u32], source: Os, target: Os) -> PreparedFile;
```

규칙 (스펙 §8, §9):
1. `secrets::mask(content, reveal)`로 마스킹. `masked`는 `detect` 결과 중 `reveal`에 없는 줄. 같은 줄은 하나.
2. `source.same_kind(target)`가 false일 때만 OS 간 변환을 한다.
   - `item.provider == "git"`이고 파일 이름이 `.gitconfig` 또는 `config`이면, `os_specific_lines`가 찾은 줄을 **그 자리에서 한 줄로** 바꾼다(줄 번호 유지):
     `<원래 들여쓰기># [repot] <원래 줄 trim>  # <key> is OS-specific; on <os_label(target)> try: <제안>`
     제안이 없으면 `…  # <key> is OS-specific; adjust it for <os_label(target)>`.
     제안 값: `credential.helper` → macOS `osxkeychain`, Windows `manager`, Linux `libsecret`; `core.autocrlf` → Windows `true`, 그 외 `input`; 나머지 키는 제안 없음.
   - 파일 이름이 `keybindings.json`이고 출발·목적지 중 하나만 macOS면 `KeybindingsMayDiffer`.
3. 마스킹 후 변환 순서라서 마스킹된 줄 번호와 결과 파일의 줄 번호가 같다. 줄바꿈 문자는 원본 그대로 유지한다.

- [ ] **Step 1: 실패하는 테스트 작성**

### Task 4: bash 스크립트 렌더러

**Files:**
- Create: `crates/core/src/export/script/mod.rs`, `crates/core/src/export/script/bash.rs`
- Test: `crates/core/tests/export_bash_test.rs`, 스냅샷 `crates/core/tests/snapshots/`

**Interfaces:**
- Consumes: Task 1 `Step`, `guide_url`; Task 2 `bash_path`, `bash_quote`, `display_path`, `os_label`; Task 3 `MaskedLine`, `ExportNote`
- Produces:

```rust
pub struct ScriptHeader { pub repot_version: String, pub source: Os, pub target: Os, pub generated_at: String }
pub struct ScriptPlan { pub header: ScriptHeader, pub steps: Vec<Step>, pub masked: Vec<MaskedLine>, pub notes: Vec<ExportNote> }
impl Step { pub fn label(&self, target: Os) -> String }   // 예: "brew install ripgrep", "copy ~/.zshrc"
pub fn render_bash(plan: &ScriptPlan) -> String;          // macOS·Linux 목적지
```

`label` 형식: `brew tap <n>` / `scoop bucket add <n>`, `<manager> install <n>`(cask는 `brew install --cask <n>`), `<tool> install <runtime> <version>`, `<manager> install -g <n>`(npm·pnpm) 또는 `<manager> install <n>`(pipx·cargo), `<code|cursor> --install-extension <id>`, `copy <display_path>`, `git clone <url>`.

**스크립트 골격** (이 순서로 출력. 헬퍼는 그대로 쓴다):

```bash
#!/usr/bin/env bash
# Generated by Repot {version} on {generated_at}
# Source: {os_label(source)} -> Target: {os_label(target)}
# Review this script before running it. Usage: ./restore.sh [--yes]

DIR="$(cd "$(dirname "$0")" && pwd)"
STAMP="$(date +%Y%m%d%H%M%S)"
OK_LIST=""; SKIP_LIST=""; FAIL_LIST=""; FAILED=0
have() { command -v "$1" >/dev/null 2>&1; }
record_ok()   { OK_LIST="$OK_LIST  - $1
"; echo "  ok: $1"; }
record_skip() { SKIP_LIST="$SKIP_LIST  - $1
"; echo "  skipped: $1"; }
record_fail() { FAIL_LIST="$FAIL_LIST  - $1
"; FAILED=1; echo "  FAILED: $1"; }
missing() { echo "  $1 not found. Install it first: $2"; }
copy_file() {
  src="$DIR/files/$1"; dest="$2"
  if [ -f "$dest" ] && cmp -s "$src" "$dest"; then return 2; fi
  [ -f "$src" ] || return 1
  mkdir -p "$(dirname "$dest")" || return 1
  if [ -e "$dest" ]; then cp -p "$dest" "$dest.repot-backup-$STAMP" || return 1; fi
  cp "$src" "$dest"
}
```

이어서:
1. **사전 점검**: `uname -s`가 목적지와 다르면(macOS `Darwin`, Linux `Linux`) 경고 후 `exit 1`.
2. **계획 출력과 확인**: `This script will:` 아래에 모든 단계의 `label`을 한 줄씩. `--yes`가 아니면 `Continue? [y/N] ` → `y`/`Y`가 아니면 `exit 0`.
3. **섹션별 실행**: Section마다 `== Packages ==` 같은 머리말. 같은 도구를 쓰는 연속 단계는 `if have <cmd>; then …단계들… else missing <도구> <guide_url>; record_skip <각 단계 label> …; fi`로 묶는다. 단계 하나의 형식:

```bash
if <이미 설치 확인> >/dev/null 2>&1; then record_skip '<label>'
elif <설치 명령>; then record_ok '<label>'
else record_fail '<label>'; fi
```

4. **요약**: `Summary` 아래 OK/Skipped/Failed 목록. `masked`가 있으면 `Fill in these masked secrets:`와 `  - files/<file> line <n> (<name 또는 "value">)` 목록. `notes`가 있으면 `Notes:` 아래 노트마다 한 줄(`files/<file> line <n>: <key> was commented out because it is OS-specific.` / `files/<file>: key bindings may use Cmd vs Ctrl differently on this OS.`).
5. `exit $FAILED`

**단계별 명령** (모든 값은 `bash_quote`):

| Step | 도구 확인 | 이미 설치 확인 | 설치 |
|---|---|---|---|
| AddTap brew | `have brew` | `brew tap \| grep -qx <n>` | `brew tap <n>` |
| InstallPackage brew Formula / Cask | `have brew` | `brew list --formula <n>` / `brew list --cask <n>` | `brew install <n>` / `brew install --cask <n>` |
| InstallPackage apt | `have apt-get` | `dpkg -s <n>` | `sudo apt-get install -y <n>` |
| InstallPackage dnf | `have dnf` | `rpm -q <n>` | `sudo dnf install -y <n>` |
| InstallPackage pacman | `have pacman` | `pacman -Q <n>` | `sudo pacman -S --needed --noconfirm <n>` |
| InstallRuntime nvm | 섹션 시작에서 `export NVM_DIR="${NVM_DIR:-$HOME/.nvm}"; [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"` 후 `have nvm` | `nvm ls <v>` | `nvm install <v>` (+ default면 `&& nvm alias default <v>`) |
| InstallRuntime fnm | `have fnm` | `fnm list \| grep -q 'v'<v>` | `fnm install <v>` (+ `&& fnm default <v>`) |
| InstallRuntime volta | `have volta` | `volta list <runtime> --format plain \| grep -q <runtime>'@'<v>` | `volta install <runtime>'@'<v>` |
| InstallRuntime pyenv | `have pyenv` | `pyenv versions --bare \| grep -qx <v>` | `pyenv install <v>` (+ `&& pyenv global <v>`) |
| InstallRuntime rustup | `have rustup` | `rustup toolchain list \| grep -q '^'<v>` | `rustup toolchain install <v>` (+ `&& rustup default <v>`) |
| InstallRuntime sdkman | 섹션 시작에서 `export SDKMAN_DIR="${SDKMAN_DIR:-$HOME/.sdkman}"; [ -s "$SDKMAN_DIR/bin/sdkman-init.sh" ] && . "$SDKMAN_DIR/bin/sdkman-init.sh"` 후 `have sdk` | `[ -d "$SDKMAN_DIR/candidates/"<runtime>'/'<v> ]` | `sdk install <runtime> <v>` (+ `&& sdk default <runtime> <v>`) |
| InstallGlobal npm / pnpm | `have npm` / `have pnpm` | `npm ls -g --depth=0 <n>` / `pnpm ls -g --depth=0 \| grep -q '^'<n>' '` | `npm install -g <n>` / `pnpm add -g <n>` |
| InstallGlobal pipx / cargo | `have pipx` / `have cargo` | `pipx list --short \| grep -q '^'<n>' '` / `cargo install --list \| grep -q '^'<n>' v'` | `pipx install <n>` / `cargo install <n>` |
| InstallExtension | `have code` / `have cursor` | `<cli> --list-extensions \| grep -qix <id>` | `<cli> --install-extension <id>` |
| CopyFile | (없음) | 아래 형식 | 아래 형식 |
| GitClone | `have git && [ -d "$HOME/.oh-my-zsh" ]`(아니면 `missing oh-my-zsh https://ohmyz.sh`) | `[ -d <bash_path> ]` | `git clone <url> <bash_path>` |

(`<v>`, `<n>` 자리는 `bash_quote`한 값이며, `'^'<n>' '`처럼 따옴표 문자열을 이어 붙여 패턴을 만든다.)

```bash
elif [ $rc -eq 2 ]; then record_skip 'copy ~/.zshrc'

```

**Files:**

- Test: `crates/core/tests/export_ps_test.rs`

**Interfaces:**
- Consumes: Task 4 `ScriptPlan`, `Step::label`; Task 2 `ps_path`, `ps_quote`
- Produces: `pub fn render_powershell(plan: &ScriptPlan) -> String` — Windows 목적지

**골격** (헬퍼는 그대로):

```powershell
# Generated by Repot {version} on {generated_at}
# Source: {source} -> Target: Windows
# Review this script before running it. Usage: powershell -ExecutionPolicy Bypass -File restore.ps1 [-Yes]
param([switch]$Yes)
$ErrorActionPreference = 'Continue'
$Dir = Split-Path -Parent $MyInvocation.MyCommand.Path
$Stamp = Get-Date -Format 'yyyyMMddHHmmss'
$script:Ok = @(); $script:Skipped = @(); $script:Failed = @()
function Test-Have($Name) { [bool](Get-Command $Name -ErrorAction SilentlyContinue) }
function Add-Ok($Label) { $script:Ok += $Label; Write-Host "  ok: $Label" }
function Add-Skip($Label) { $script:Skipped += $Label; Write-Host "  skipped: $Label" }
function Add-Fail($Label) { $script:Failed += $Label; Write-Host "  FAILED: $Label" }
function Write-Missing($Name, $Url) { Write-Host "  $Name not found. Install it first: $Url" }
function Test-Admin { ([Security.Principal.WindowsPrincipal][Security.Principal.WindowsIdentity]::GetCurrent()).IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator) }
function Copy-RepotFile($Src, $Dest) {
  $from = Join-Path $Dir (Join-Path 'files' $Src)
  if (-not (Test-Path $from)) { return 1 }
  if ((Test-Path $Dest) -and ((Get-FileHash $from).Hash -eq (Get-FileHash $Dest).Hash)) { return 2 }
  try {
    New-Item -ItemType Directory -Force -Path (Split-Path -Parent $Dest) | Out-Null
    if (Test-Path $Dest) { Copy-Item $Dest "$Dest.repot-backup-$Stamp" -ErrorAction Stop }
    Copy-Item $from $Dest -ErrorAction Stop
    return 0
  } catch { return 1 }
}
```

이어서 bash와 같은 흐름: 사전 점검(`$env:OS -ne 'Windows_NT'`이면 `exit 1`), 계획 출력, `-Yes`가 아니면 `Read-Host 'Continue? [y/N]'`, 섹션 실행, 요약(bash와 같은 문구), `if ($script:Failed.Count -gt 0) { exit 1 } else { exit 0 }`.

**관리자 권한**: choco 단계가 있으면 choco 묶음 시작에서 `if (-not (Test-Admin)) { Write-Host '  choco requires an Administrator PowerShell. Skipping choco packages.'; <각 단계 Add-Skip> } else { … }`.

**단계 형식**:
- 종료 코드로 확인하는 경우:

```powershell
& <확인 명령> *> $null
if ($LASTEXITCODE -eq 0) { Add-Skip '<label>' }
else { & <설치 명령>; if ($LASTEXITCODE -eq 0) { Add-Ok '<label>' } else { Add-Fail '<label>' } }
```

- 출력에 포함되는지로 확인하는 경우: `if (& <cmd> 2>$null | Select-String -SimpleMatch <값> -Quiet) { Add-Skip … } else { … }`

**단계별 명령** (모든 값은 `ps_quote`):

| Step | 도구 확인 | 이미 설치 확인 | 설치 |
|---|---|---|---|
| InstallPackage winget | `Test-Have winget` | 종료 코드: `winget list --id <n> --exact` | `winget install --id <n> --exact --accept-package-agreements --accept-source-agreements` |
| AddTap scoop | `Test-Have scoop` | 출력 포함: `scoop bucket list`에 `<n>` | `scoop bucket add <n>` |
| InstallPackage scoop | `Test-Have scoop` | 종료 코드: `scoop prefix <n>` | `scoop install <n>` |
| InstallPackage choco | `Test-Have choco` + 관리자 | 출력 포함: `choco list --exact <n> --limit-output`에 `<n>` | `choco install <n> -y` |
| InstallRuntime nvm-windows | `Test-Have nvm` | 출력 포함: `nvm list`에 `<v>` | `nvm install <v>` (+ default면 `; nvm use <v>`) |
| InstallRuntime fnm | `Test-Have fnm` | 출력 포함: `fnm list`에 `v<v>` | `fnm install <v>` (+ `; fnm default <v>`) |
| InstallRuntime volta | `Test-Have volta` | 출력 포함: `volta list <runtime> --format plain`에 `<runtime>@<v>` | `volta install <runtime>@<v>` |
| InstallRuntime pyenv-win | `Test-Have pyenv` | 출력 포함: `pyenv versions --bare`에 `<v>` | `pyenv install <v>` (+ `; pyenv global <v>`) |
| InstallRuntime rustup | `Test-Have rustup` | 출력 포함: `rustup toolchain list`에 `<v>` | `rustup toolchain install <v>` (+ `; rustup default <v>`) |
| InstallGlobal npm / pnpm / pipx / cargo | `Test-Have <cmd>` | 출력 포함: `npm ls -g --depth=0` / `pnpm ls -g --depth=0` / `pipx list --short` / `cargo install --list`에 `<n>` | `npm install -g <n>` / `pnpm add -g <n>` / `pipx install <n>` / `cargo install <n>` |
| InstallExtension | `Test-Have code` / `cursor` | 출력 포함: `<cli> --list-extensions`에 `<id>` | `<cli> --install-extension <id>` |

`build_export` 순서:
1. `req.items` 순서대로, `selection.items`에 있는 항목만.
2. `availability(item, source, target)`가 `Unavailable`이면 `Unavailable` 경고, 건너뜀.

5. `steps_for`로 단계를 모으고 `sort_steps`.
6. `Format::Script`: 목적지가 Windows면 `restore.ps1`, 아니면 `restore.sh`(`executable: true`). `Format::Manifest`: `render_manifests`.
7. 파일 순서: 스크립트 또는 매니페스트 파일들, 그다음 `files/…`(경로순).
