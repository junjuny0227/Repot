# Repot 계획 7: 다국어 UI 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 데스크톱 앱과 제품 사이트를 영어(원본), 한국어(`ko`), 일본어(`ja`), 중국어 간체(`zh-Hans`)로 보여준다. 언어를 하나 더하는 일은 로캘 JSON 파일 하나를 더하고 목록에 한 줄을 넣는 것으로 끝나게 한다.

**Architecture:** i18n 라이브러리 없이 로캘마다 JSON 파일 하나(`apps/desktop/src/locales/<locale>.json`, `apps/site/src/locales/<locale>.json`)에 메시지를 둔다. 평범한 중첩 JSON이라 나중에 Crowdin·Weblate·i18next에 그대로 넣을 수 있다. TypeScript 메시지 타입은 `en.json`에서 끌어낸다(`typeof en`). 작은 접근자, `{name}` 자리표시자를 채우는 `format(msg, vars)`, `Intl.PluralRules`로 고르는 복수형 객체(`{"one": "…", "other": "…"}`), 숫자·목록용 `Intl`만 쓴다. 내보내는 파일(`restore.sh`/`restore.ps1`, 매니페스트, 내보내기 README)은 영어로 남긴다. core의 `catalog` 설명에는 안정된 id를 붙이고, UI가 id로 번역을 찾되 없으면 core의 영어 문장을 보여준다. 사이트는 로캘마다 정적 HTML(`/Repot/`, `/Repot/ko/`, `/Repot/ja/`, `/Repot/zh-Hans/`)을 Vite 멀티 페이지로 만든다.

**Tech Stack:** React, TypeScript, Vite, Vitest, `Intl`(PluralRules, NumberFormat, ListFormat, Locale), Rust(serde), pnpm

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` (§5 계층 경계, §6 도메인 모델, §10 공통, §11 UI, §14 배포)

**선행 계획:** 계획 3(데스크톱 앱), 계획 6(제품 사이트)

## Global Constraints

- 계획 3·6의 Global Constraints를 따른다.
- **새 의존성 없음.** i18n 라이브러리(i18next, FormatJS, react-intl 등), 폰트 패키지, 웹 폰트를 더하지 않는다. `Intl`과 JSON import만 쓴다. `pnpm-lock.yaml`과 `Cargo.lock`은 바뀌지 않아야 한다.
- 지원 로캘은 `en`, `ko`, `ja`, `zh-Hans` 넷이다. 원본은 `en.json`이고, 다른 로캘은 `en.json`과 키·자리표시자 이름이 정확히 같아야 한다. 복수형 객체는 그 로캘의 `Intl.PluralRules`가 쓰는 범주를 정확히 가진다(`en`은 `one`/`other`, `ko`·`ja`·`zh-Hans`는 `other`). 빈 문자열은 없다.
- **영어로 남는 것:** 생성 파일(스크립트 출력 문구, 매니페스트, 내보내기 README)은 §10대로 UI 언어와 상관없이 영어다. 로컬 도구가 준 패키지 설명(brew, npm 등), Provider 실패 메시지와 stderr 원문, Tauri가 돌려주는 오류 문자열도 원문 그대로 둔다. 실행 명령(`./restore.sh`, `powershell -ExecutionPolicy Bypass -File restore.ps1`), 파일·도구 이름(`Repot`, Homebrew, VS Code, `restore.sh`)은 번역하지 않는다.
- core는 문장을 새로 만들지 않는다. `catalog` 영어 설명(문서화된 예외)은 그대로 core에 두고, `Item`에 `catalog_id`(직렬화 `catalogId`)만 더한다. 내보내기는 지금처럼 `description`을 쓰지 않는다.
- 데스크톱 로캘 결정: 저장된 선택(`localStorage` `repot.locale`) > `navigator.languages`에서 처음 맞는 언어 > `en`. `ko*` → `ko`, `ja*` → `ja`, 중국어는 `Intl.Locale(tag).maximize().script`가 `Hans`인 것(`zh`, `zh-CN`, `zh-SG`, `zh-Hans-*`) → `zh-Hans`. `zh-TW`, `zh-HK`, `zh-MO`, `zh-Hant-*`는 아직 번체가 없으므로 맞는 언어로 치지 않는다(다음 선호 언어로 넘어가고, 없으면 `en`). `en*`가 먼저 나오면 `en`이다. 고른 로캘은 `<html lang>`에 쓴다.
- 사이트는 URL이 로캘을 정한다. 자동 리디렉션은 하지 않는다. `/Repot/`(영어)에 처음 왔을 때만, 브라우저가 다른 지원 언어를 더 원하면 작은 제안 배너를 보여주고 닫거나 고른 결과를 `localStorage` `repot.site.locale`에 기억한다.
- 글꼴: 웹 폰트 없이 시스템 글꼴만 쓴다. `tokens.css`에 `:lang()`별 글꼴 목록을 둔다. macOS는 `-apple-system`이 `lang`에 맞춰 Apple SD Gothic Neo·Hiragino·PingFang을 고르고, Windows·Linux용으로 Malgun Gothic, Yu Gothic UI, Microsoft YaHei UI, Noto Sans CJK를 덧붙인다. 한국어는 `word-break: keep-all`, CJK에서는 SF용 음수 자간을 0으로 둔다.
- 번역 품질: 직역이 아닌 그 언어 사용자가 매일 보는 앱 문구로 쓴다. 한국어는 라벨·버튼은 짧은 명사형, 문장은 합니다체. 일본어는 문장은 です/ます, 라벨은 간결하게. 중국어는 간체, 중국 본토 표기(软件包, 运行时, 导出). 버튼·사이드바가 넘치지 않는지 화면으로 확인한다.
- AGENTS.md는 보호 파일이라 이 계획의 PR에서 고치지 않는다. 바꿀 줄은 계획 7 완료 보고에 적고 사람이 반영한다.

## 결정과 이유

### 라이브러리 없이 로캘 JSON

| 방법 | 장점 | 단점 |
|---|---|---|
| i18next / FormatJS | ICU 문법, 생태계 | 새 의존성, 번들 증가, 계획 3·6의 의존성 제약 위반 |
| TS 객체(`strings.ts`를 로캘별로 복사) | 타입이 바로 나옴 | 번역 도구가 읽지 못하고, 함수 안 문장이 번역자에게 보이지 않음 |
| **로캘별 JSON + 작은 접근자** | 번역 도구 호환, 타입은 `typeof en`, 의존성 없음 | 자리표시자·복수형 검사를 직접 테스트해야 함 |

세 번째를 고른다. 메시지는 평범한 중첩 JSON이고, 자리표시자는 `{name}`, 복수형은 CLDR 범주 이름을 키로 쓰는 객체라 i18next JSON v4나 Crowdin의 중첩 JSON과 거의 같은 모양이다. 나중에 라이브러리로 옮겨도 파일을 다시 쓰지 않는다.

모든 로캘 JSON을 번들에 함께 넣는다(데스크톱 각 5KB 안팎, 사이트 각 8KB 안팎). 첫 화면을 그리기 전에 메시지가 있어야 하고, 사이트의 언어 제안 배너는 다른 로캘 문구가 필요하기 때문이다. 크기가 문제가 되면 `import.meta.glob`의 lazy 로드로 바꾼다.

### 데스크톱 접근자

- `src/i18n.ts`: `Locale`, `LOCALES`(코드와 자기 언어 이름), `resolveLocale(saved, languages)`, `getLocale()`, `setLocale(locale)`(메시지 교체, `<html lang>`, 저장, 구독자 알림), `useLocale()`(`useSyncExternalStore`), `messages()`, `format(msg, vars)`(숫자 값은 `Intl.NumberFormat`), `plural(msg, count, vars)`(`Intl.PluralRules`).
- `src/strings.ts`는 지금 API(`S`, `osLabel`, `statusText`, `findingText` …)를 그대로 유지하고 내부만 현재 로캘 메시지를 읽게 바꾼다. 화면 컴포넌트는 고치지 않아도 되고, `S.xxx`는 현재 로캘 값을 돌려주는 getter다. App이 `useLocale()`을 구독해 로캘이 바뀌면 다시 그린다.
- 문장 조각을 이어 붙이지 않는다. `"Line {line}: {text}"`처럼 문장 전체를 메시지 하나로 두어 어순이 다른 언어도 자연스럽게 쓸 수 있게 한다.

### catalog id

- 지금 `catalog::describe(key)`의 키(`runtime:node`, `file:zshrc`, `plugin:oh-my-zsh` …)가 이미 안정된 이름이다. 이것을 그대로 `Item.catalog_id`로 내보낸다. 영어 설명은 `Item.description`에 계속 담겨 CLI 재사용과 번역 누락 때의 대체 문구가 된다.
- UI는 `itemDescription(item)` = 현재 로캘 `catalog[catalogId]` → 없으면 `item.description` → 없으면 "설명 없음". 검색도 화면에 보이는 설명으로 한다.
- `en.json`의 `catalog`는 core 영어 문장과 같아야 한다. Vitest가 `crates/core/src/catalog.rs`를 텍스트로 읽어 id와 문장이 `en.json`과 똑같은지 확인한다. core에 설명을 더하고 `en.json`을 잊으면 테스트가 실패한다.
- 내보내기는 `description`을 쓰지 않으므로(`export/` 모듈) 스냅샷은 바뀌지 않아야 한다.

### 언어 선택 위치(데스크톱)

시작 화면 아래쪽에 지구본 아이콘이 붙은 작은 팝업 버튼을 두고, 검토 화면 사이드바 맨 아래에도 같은 팝업을 둔다. 시작 화면은 앱을 열 때마다 지나가고, 검토 화면은 가장 오래 머무는 곳이다. 툴바는 이미 목적지 OS와 다음 버튼으로 차 있어서 두지 않는다. 각 `<option>`에는 `lang`을 달아 자기 언어 이름(English, 한국어, 日本語, 简体中文)을 맞는 글꼴로 보여준다.

### 사이트

- `index.html`, `ko/index.html`, `ja/index.html`, `zh-Hans/index.html`을 Vite `build.rollupOptions.input`으로 묶는다. 각 HTML은 `<html lang>`만 다르고, `vite.config.ts`의 작은 플러그인이 `<!-- repot:head -->` 자리에 로캘 JSON의 `<title>`, meta description, canonical, hreflang 대체 링크 넷과 `x-default`(`/Repot/`)를 채운다. 문구의 원본은 JSON 하나로 남는다.
- `main.tsx`는 `document.documentElement.lang`으로 로캘을 정해 `App`에 넘긴다. 사이트 본문은 지금처럼 클라이언트에서 그린다.
- 언어 전환: 헤더 오른쪽에 지구본 메뉴(`<details>`, JS 없이 동작하는 링크 목록), 푸터에 언어 링크 목록. 링크를 누르면 선택을 저장한다.
- 도구 이름 목록(Homebrew, winget …)은 번역하지 않는 상수로 두고 `Intl.ListFormat`(`type: "unit"`)으로 이어 로캘 문장 부호(`、`)를 따른다.
- 푸터에 "Help improve translations" 링크(GitHub issues).

## Review Focus

1. **로캘 키 누락·불일치**: 번역 파일에서 키가 빠지거나 `{count}`를 `{num}`으로 바꾸면 화면에 키나 자리표시자가 그대로 나온다. → Task 1 `i18n.test.ts` 키·자리표시자·복수형·빈 문자열 검사, Task 4·5에서 로캘이 늘 때 같은 테스트가 다시 돈다.
2. **영어 화면 회귀**: 문구를 JSON으로 옮기며 영어가 한 글자라도 바뀌면 안 된다(복수형 `1 of 1 item selected`만 의도한 변화). → Task 1 기존 `strings.test.ts`·`screens.test.tsx`가 그대로 통과, 시작·검토·내보내기·완료 영어 캡처 비교.
3. **내보내기 결과가 UI 언어를 따라감**: 스크립트·README가 번역되면 안 된다. → Task 2 스냅샷 무변경, 생성 경로가 로캘을 받지 않음(`preview_export`/`export` 인자 그대로).
4. **catalog 영어와 `en.json` 어긋남**: → Task 2 `catalog matches core` 테스트.
5. **중국어 번체 사용자에게 간체 강제**: `zh-TW`·`zh-HK`는 `zh-Hans`가 되면 안 된다. → Task 1 `resolveLocale` 표 테스트.
6. **사이트 SEO 태그 오류**: 로캘 페이지의 `lang`, canonical, hreflang이 서로 어긋나면 검색엔진이 페이지를 합치거나 버린다. → Task 5 `head.test.ts`, 빌드 결과 `grep`, 배포 뒤 `curl`.
7. **사이트 자동 리디렉션**: 제안 배너는 `/Repot/`에서만, 저장된 선택이 없을 때만, 이동은 사용자가 누를 때만. → Task 5 `suggestion.test.ts`.
8. **CJK 글자 넘침**: 버튼·사이드바·세그먼트가 잘리거나 이상하게 줄바꿈되면 안 된다. → Task 4·5 화면 캡처 점검.
