# Repot 계획 14: JetBrains IDE 설정과 플러그인

**Goal:** IntelliJ IDEA, WebStorm, PyCharm 등 JetBrains IDE의 설정(코드 스타일, 키맵, 색 테마, 라이브 템플릿, 글꼴·테마 선택)과 사용자가 설치한 플러그인을 스캔하고, 새 기기에서 복원 스크립트로 되살린다.

**Architecture:** 새 Provider `jetbrains`(분류 Editor)가 IDE별 최신 버전 설정 폴더를 읽는다. 플러그인 ID는 플러그인 jar 안의 `META-INF/plugin.xml`에만 있으므로 zip을 읽는다. 복원은 IDE 명령줄 `installPlugins`로 플러그인을 설치하고, 설정 파일은 대상 기기에서 그 IDE의 가장 최신 설정 폴더(없으면 출발 기기와 같은 버전 폴더)에 복사한다. 버전 폴더는 스크립트가 실행할 때 고른다.

**Tech Stack:** Rust(`zip` 크레이트 추가), React, TypeScript

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` §2·7·9·10·13·15

## Global Constraints

- **새 의존성 하나:** `zip = { version = "9", default-features = false, features = ["deflate-flate2-zlib-rs"] }`(읽기, 순수 Rust 압축 해제). 테스트 fixture jar를 만들 때도 같은 크레이트를 쓴다. 다른 의존성은 추가하지 않는다.
- jar 읽기도 `Env`를 거친다. `Env::read_bytes`를 더하고 `FakeEnv::with_bytes`로 테스트한다.
- 앱은 기기를 바꾸지 않는다. 플러그인 설치와 설정 복사는 사용자가 실행하는 스크립트가 한다.
- 문구는 네 로캘에 둔다. core는 문장을 만들지 않는다(플러그인 이름과 설명은 plugin.xml에서 가져온 원문).
- `repot.json` v1은 enum 값·variant 추가만 한다. 이전 버전 앱은 모르는 항목을 건너뛰고 개수를 알린다.

## 결정과 이유

**대상 IDE.** 폴더 이름 접두어로 구분한다: `IntelliJIdea`, `IdeaIC`, `WebStorm`, `PyCharm`, `PyCharmCE`, `GoLand`, `RustRover`, `CLion`, `PhpStorm`, `RubyMine`, `DataGrip`, `Rider`. Android Studio(Google 폴더)와 Fleet는 다루지 않는다. 같은 IDE가 여러 버전이면 가장 최신 버전 폴더만 읽는다(`2026.1` > `2025.3`).

**설정 폴더 위치.**
- 설정: macOS `~/Library/Application Support/JetBrains/<IDE><버전>`, Windows `%APPDATA%\JetBrains\<IDE><버전>`, Linux `~/.config/JetBrains/<IDE><버전>`
- 플러그인: macOS·Windows는 설정 폴더 안 `plugins/`, Linux는 `~/.local/share/JetBrains/<IDE><버전>/`

**옮기는 설정 파일.** 기기와 무관한 것만: `codestyles/*.xml`, `keymaps/*.xml`, `colors/*.icls`, `templates/*.xml`, `options/`의 `editor-font.xml`·`console-font.xml`·`colors.scheme.xml`·`ui.lnf.xml`. 경로·JDK·최근 프로젝트·계정이 든 `options/`의 나머지와 OS별 하위 폴더(`options/mac` 등)는 옮기지 않는다. 비밀정보 감지는 다른 설정 파일과 같다.

**복원할 버전 폴더.** 대상 기기에 같은 IDE 폴더가 있으면 그중 가장 최신 버전에, 없으면 출발 기기의 버전 이름 그대로 만든다. 나중에 더 새 버전을 처음 실행하면 IDE가 "이전 설정 가져오기"로 그 폴더를 읽는다. 그래서 항목은 버전과 무관한 이름(`jetbrains/IntelliJIdea/codestyles/Default.xml`)으로 비교·저장하고, 출발 버전은 대체 이름으로만 쓴다.

**플러그인.** 플러그인 폴더(또는 단일 jar)마다 jar 안 `META-INF/plugin.xml`의 `<id>`, `<name>`, `<version>`, `<description>`(태그를 지운 첫 문장)을 읽는다. 읽지 못하면 그 플러그인만 건너뛴다. 복원은 `<명령> installPlugins <id>`이고, 이미 있음은 대상 플러그인 폴더에 같은 이름의 폴더·jar가 있는지로 판단한다.

**IDE 명령 찾기.** PATH의 `idea`·`webstorm` 등, Toolbox 스크립트 폴더, 설치 위치(macOS `/Applications`·`~/Applications`의 앱 번들, Windows `Program Files\JetBrains`·`%LOCALAPPDATA%\Programs`, Linux Toolbox)를 차례로 찾는다. 없으면 그 IDE의 플러그인은 "Not done (<IDE> not found)"이다. IDE가 열려 있으면 `installPlugins`가 실패하므로 스크립트가 해당 구간 앞에 IDE를 닫으라고 안내한다.

**사용 가능 여부.** JetBrains IDE는 세 OS 모두 있으므로 `Portability::Any`다. 다른 OS로도 설정과 플러그인을 옮긴다.

**매니페스트 형식.** `jetbrains-plugins.txt`(`<IDE> <플러그인 id>` 줄)와 설정 파일 묶음(`files/jetbrains/...`)을 쓰고 README에 설치 명령을 적는다.

## 모델 변경

```rust
pub enum JetBrainsIde { IntelliJIdea, IdeaIc, WebStorm, PyCharm, PyCharmCe, GoLand, RustRover, CLion, PhpStorm, RubyMine, DataGrip, Rider }
ItemDetails::IdePlugin { ide: JetBrainsIde, folder: String }      // folder: 대상에서 이미 있음 확인용
TargetPath::JetBrains { ide: JetBrainsIde, version: String, rel: PathBuf }
Step::InstallIdePlugin { ide, id, folder }
```

- 항목 id: `jetbrains:<ide>:plugin:<plugin id>`, `jetbrains:<ide>:file:<rel>`
- v1: `DetailsV1::IdePlugin`, `TargetPathV1::JetBrains` 추가. `folder`, `rel`, `version`도 열 때 안전성 검사(경로 구분자·`..` 금지, 버전은 `숫자.숫자`)를 한다.
