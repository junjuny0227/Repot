# Repot 계획 5: CI와 배포 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** macOS·Windows·Ubuntu에서 테스트와 실제 스캔을 자동으로 돌리고, 생성된 복원 스크립트를 lint·실행해 검증하며, 태그를 push하면 설치 파일이 GitHub Releases 초안으로 올라가게 한다.

**Architecture:** GitHub Actions 워크플로 두 개. `ci.yml`(push·PR): Rust 테스트 매트릭스, 프론트엔드 검사, 러너 실제 스캔, 스크립트 lint와 스모크 실행. `release.yml`(`v*` 태그): 버전 일치 검사 후 `tauri-action`으로 4개 대상 빌드. 스크립트 샘플과 스모크용 내보내기 폴더는 `repot-core` 예제가 만든다.

**Tech Stack:** GitHub Actions, `dtolnay/rust-toolchain`, `Swatinem/rust-cache`, `pnpm/action-setup`, `actions/setup-node`, `tauri-apps/tauri-action`, shellcheck, PSScriptAnalyzer

**Spec:** `docs/specs/2026-11-02-repot-mvp-design.md` (§1 성공 기준, §13, §14)

**선행 계획:** 계획 1~4

## Global Constraints

- 계획 1~4의 Global Constraints를 따른다.
- 액션은 메이저 태그로 고정한다(예: `actions/checkout@v4`). Node는 22, Rust는 `rust-toolchain.toml`의 stable.
- Linux 러너에는 Tauri 2 빌드 의존성을 설치한다: `libwebkit2gtk-4.1-dev build-essential curl wget file libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev`.
- `repot-desktop`을 컴파일하려면 `apps/desktop/dist`가 있어야 하므로(Tauri가 컴파일 시점에 프론트엔드를 포함), Rust 잡에서도 `cargo` 전에 프론트엔드를 빌드한다.
- PSScriptAnalyzer는 Warning·Error 수준을 검사하되 `PSAvoidUsingWriteHost`만 제외한다(대화형 스크립트라 콘솔 출력이 의도된 동작). 스펙 §1 성공 기준 "경고 없음"의 유일한 예외다.
- 원격에 push하거나 태그를 만드는 단계는 **실행 전에 사용자에게 확인을 받는다.**
- 릴리스는 초안(draft)·사전 릴리스(prerelease)로만 만든다. 공개 전환은 사람이 한다. 코드 서명은 하지 않는다. (스펙 §14)

## Review Focus

1. **실제 러너에서 출력 형식이 fixture와 다른 도구**: 러너의 실제 brew·choco·apt·npm·pipx·cargo 출력으로 스캔했을 때 `failed`가 나오면 CI가 실패해야 한다. → Task 2 `real_scan_has_no_failures`
2. **생성 스크립트가 실제 셸에서 실행되지 않는 경우**: 문법 검사만으로는 부족하다. 실제로 실행해서 종료 코드 0, 파일 복사, 두 번째 실행의 "skipped"를 확인해야 한다. → Task 3 스모크 단계
3. **태그와 앱 버전 불일치**: `v0.2.0` 태그인데 앱 버전이 `0.1.0`이면 릴리스를 만들지 말아야 한다. → Task 4 `check-version`
4. **Windows PowerShell 5.1에서만 생기는 문법 문제**: 스모크 실행은 `pwsh`가 아니라 `powershell`(5.1)로 해야 한다. → Task 3 Windows 스모크 단계
5. **README의 설치 안내 누락**: 서명되지 않은 앱의 첫 실행 방법이 없으면 사용자가 막힌다. → Task 5

### Task 2: 러너 실제 스캔 테스트

**Files:** Create `crates/core/tests/real_scan.rs`, Modify `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: 계획 1·4 `scan`, `default_providers`, `RealEnv`, `PROVIDER_TIMEOUT`, `current_os`

- [ ] **Step 1: 테스트 작성**

```rust
#[test]
#[ignore = "runs real tools; executed in CI with --ignored"]
fn real_scan_has_no_failures() {
    let env: Arc<dyn Env> = Arc::new(RealEnv::new());
    let r = scan(env, default_providers(), PROVIDER_TIMEOUT, &|_| {});
    eprintln!("{}", serde_json::to_string_pretty(&r.providers).unwrap());
    let bad: Vec<_> = r.providers.iter()
        .filter(|p| matches!(p.status, ProviderStatus::Failed { .. } | ProviderStatus::TimedOut))
        .collect();
    assert!(bad.is_empty(), "failed providers: {bad:#?}");
    let ok = |id: &str| r.providers.iter().any(|p| p.id == id && matches!(p.status, ProviderStatus::Ok { .. }));
    let expected: &[&str] = match current_os() {
        Os::MacOs => &["brew", "npm", "cargo"],
        Os::Windows => &["choco", "npm", "cargo"],
        Os::Linux(_) => &["apt", "npm", "cargo"],
    };
    for id in expected { assert!(ok(id), "{id} should be ok on this runner"); }
}
```

- Produces:
  - `cargo run -p repot-core --example render_samples -- <out>` → `<out>/restore-macos.sh`, `<out>/restore-linux.sh`, `<out>/restore.ps1`. `Step`의 모든 variant와 모든 `PackageManager`·`RuntimeTool`·`GlobalManager`·`Editor` 조합이 최소 한 번씩 들어간 고정 계획(목적지 OS에서 생길 수 있는 조합만)과 masked·notes 1개씩.
  - `cargo run -p repot-core --example smoke_export -- <out>` → `<out>/repot-export-<date>/`. `FakeEnv`의 설정 파일 하나(`.repot-smoke`, 내용 `"smoke\n"`, target `Home(".repot-smoke")`)와 npm 전역 패키지 `cowsay` 항목을 현재 OS 목적지로 `Format::Script` 내보내기. 생성 경로를 stdout에 출력.

- [ ] **Step 2: CI 잡 추가**

`ci.yml`에 잡 `scripts`(매트릭스 3개 OS, `rust` 잡과 같은 Rust 설정, 프론트엔드 빌드 불필요):
- 모든 OS: `cargo run -p repot-core --example render_samples -- samples`
- Ubuntu: `shellcheck -s bash samples/restore-macos.sh samples/restore-linux.sh`
- Windows(`shell: powershell`):

```powershell
Install-Module PSScriptAnalyzer -Force -Scope CurrentUser
$r = Invoke-ScriptAnalyzer -Path samples/restore.ps1 -Severity Warning,Error -ExcludeRule PSAvoidUsingWriteHost
if ($r) { $r | Format-Table -AutoSize; exit 1 }
```

- macOS·Ubuntu 스모크(`shell: bash`):

```bash
mkdir -p smoke smoke-home
out=$(cargo run -q -p repot-core --example smoke_export -- smoke)
HOME="$PWD/smoke-home" bash "$out/restore.sh" --yes
test "$(cat smoke-home/.repot-smoke)" = "smoke"
HOME="$PWD/smoke-home" bash "$out/restore.sh" --yes | grep -q "skipped: copy ~/.repot-smoke"
```

- Windows 스모크(`shell: powershell` — PowerShell 5.1로 실행):

```powershell
New-Item -ItemType Directory -Force smoke | Out-Null
$out = cargo run -q -p repot-core --example smoke_export -- smoke
powershell -NoProfile -ExecutionPolicy Bypass -File "$out\restore.ps1" -Yes
if ($LASTEXITCODE -ne 0) { exit 1 }
if ((Get-Content "$HOME\.repot-smoke") -ne 'smoke') { exit 1 }
$second = powershell -NoProfile -ExecutionPolicy Bypass -File "$out\restore.ps1" -Yes | Out-String
if ($second -notmatch 'skipped: copy') { exit 1 }
```

### Task 4: 릴리스 워크플로

**Interfaces:**
- `node scripts/check-version.mjs <tag>`: `<tag>`에서 앞의 `v`를 뗀 값이 `apps/desktop/src-tauri/tauri.conf.json`의 `version`, `apps/desktop/package.json`의 `version`, `apps/desktop/src-tauri/Cargo.toml`과 `crates/core/Cargo.toml`의 `[package] version`과 모두 같으면 종료 코드 0, 하나라도 다르면 다른 파일과 값을 출력하고 1. - 잡 `build`(`needs: check`, `fail-fast: false`) 매트릭스:

| platform | args |
|---|---|
| `macos-latest` | `--target aarch64-apple-darwin` |
| `macos-latest` | `--target x86_64-apple-darwin` |
| `ubuntu-22.04` | (없음) |
| `windows-latest` | (없음) |

- 단계: checkout, Linux면 Tauri 의존성, pnpm·node 설정, `dtolnay/rust-toolchain@stable`(macOS면 `targets: aarch64-apple-darwin,x86_64-apple-darwin`), rust-cache, `pnpm install --frozen-lockfile`, `tauri-apps/tauri-action@v0`:

### Task 5: README

**Files:** Create `README.md`

**Interfaces:** 없음

구성(영어, 스펙 §14·§15 반영):
1. 제목 `Repot`, 한 줄 소개("Move your dev environment to a new machine — explained, selective, and safe.")
2. **What it does**: 스캔 → 설명과 함께 검토 → 고른 것만 → 스크립트 또는 매니페스트로 내보내기. 지원 도구 목록(스펙 §7 표의 Provider들).
3. **Principles**: 스펙 §3의 다섯 원칙을 한 줄씩(Explains everything, Never changes your machine, Conservative by default, No network, Review before you run).
4. **Install**: Releases 링크. 첫 실행 — macOS: **System Settings › Privacy & Security › Open Anyway**, Windows: **More info › Run anyway**, Linux: `chmod +x Repot_*.AppImage` 또는 `.deb` 설치. 서명되지 않은 이유(베타).
5. **Using an export**: 스크립트(`./restore.sh` / `powershell -ExecutionPolicy Bypass -File restore.ps1`), 매니페스트(`README.md` 따라가기). 스크립트를 실행 전에 읽어 보라는 안내와 마스킹된 비밀정보를 채우라는 안내.
6. **Known limitations**: 스펙 §15 다섯 항목 + 계획 4 Global Constraints의 알려진 한계 네 항목.
7. **Build from source**: Rust stable, Node 22 + pnpm, Linux는 Tauri 의존성. 명령: `pnpm install`, `pnpm --filter @repot/desktop tauri dev`, `cargo test --workspace`, `cargo run -p repot-core --example scan`.
8. **Docs**: `docs/specs/2026-11-02-repot-mvp-design.md`, `docs/plans/` 링크.
9. **License**: Apache-2.0.
